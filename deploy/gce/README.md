# Phoring on Google Cloud — Compute Engine deploy

Cohort-submission hosting: **Compute Engine + Docker + persistent disk + Caddy (HTTPS)**.
No code refactor required — runs the existing multi-stage image from GHCR
(`ghcr.io/inbharatai/phoring:latest`) that CI already builds on every tag.

> **Why GCE, not Cloud Run:** Phoring keeps all state (uploads, JSON project
> files, reports, simulation artifacts) under `/app/backend/uploads/{projects,
> reports,simulations,tasks}` and runs simulations as long-lived subprocesses
> (up to ~45 min). Cloud Run's ephemeral filesystem + GCS-FUSE (no multi-writer
> POSIX concurrency) + 60-min request ceiling fight that. A normal persistent
> disk on a VM is the safe, no-refactor choice for the deadline.
> *(Cloud Run + Cloud Storage + Cloud SQL + Cloud Tasks is the later phase.)*

## 1. Create the VM (one command)

Run from **Cloud Shell** (or any machine with `gcloud` authed to project
`phoring-501306`). From this directory:

```bash
gcloud auth login
gcloud config set project phoring-501306
bash create-vm.sh
```

`create-vm.sh` provisions, idempotently:

- Static external IP `phoring-ip` (region `asia-south1`)
- Firewall rules `allow-http-phoring` / `allow-https-phoring` (tag `phoring`)
- VM `phoring` — `e2-standard-2`, `asia-south1-a`, Debian 12, 30 GB boot
- Attached **100 GB persistent disk** (`phoring-data-1`)
- `vm-setup.sh` as the first-boot startup script (installs Docker + Caddy,
  formats/mounts the disk, writes the Caddyfile + `phoring.service`)

Set the host up front (drives Caddy auto-TLS):

```bash
DOMAIN=phoring.in bash create-vm.sh
```

If you don't set `DOMAIN`, Caddy serves plain HTTP on `:80` until you add one.

> **Note:** in the live deployment, `phoring.in` points at the **GKE** Ingress
> (the primary). This GCE VM is the **secondary** host, reachable at its bare
> IP `http://35.200.201.102`. If you want HTTPS on this VM too, use a different
> host (e.g. `gce.phoring.in`) so it doesn't collide with the GKE Ingress.

## 2. Point your domain at the static IP

```
phoring.in   A   <the IP printed by create-vm.sh>
```

Caddy provisions the Let's Encrypt certificate automatically on first request.

## 3. Drop in your secrets

```bash
gcloud compute ssh phoring --zone=asia-south1-a
sudo cp /opt/phoring/.env.example /opt/phoring/.env
sudo nano /opt/phoring/.env        # fill LLM_API_KEY, ZEP_API_KEY, SERPER_API_KEY, ...
sudo systemctl restart phoring
```

## 4. Verify

```bash
# On the VM:
curl -s http://127.0.0.1:10000/health | head
# From outside, once DNS is live:
curl -s https://phoring.in/health
```

`/health` returns JSON; `llm_configured` / `zep_configured` should both be `true`
once secrets are in. The landing page is at `/`, the workspace at `/app`,
the API under `/api/*`.

## 5. Ops

| Task | Command |
|---|---|
| Tail container logs | `sudo journalctl -u phoring -f` |
| Tail Caddy logs | `sudo journalctl -u caddy -f` |
| Restart app | `sudo systemctl restart phoring` |
| Restart proxy | `sudo systemctl restart caddy` |
| Update image (after a new GHCR tag) | `sudo systemctl restart phoring` (unit pulls `:latest`) |
| Upgrade on OOM | `gcloud compute instances set-machine-type phoring --zone=asia-south1-a --machine-type=e2-standard-4` (requires `gcloud compute instances stop` first) |

> **GHCR visibility:** if `docker pull ghcr.io/inbharatai/phoring:latest` 401s,
> make the package public at GitHub → your profile → Packages → phoring →
> Package settings, or `docker login ghcr.io` with a PAT on the VM.
